### Phase 2 — Ordered bounded renderer stream transport

**Status: implementation slice complete; real Windows Electron performance acceptance remains open.**

The renderer stream publication path now uses one bounded FIFO of `{ event, subscriptionKey }` records. Distinct `assistantDelta` and `toolUpdated` callbacks are appended, never overwritten by session key. A short trailing timer still batches transport work, but the batch drains in FIFO order. Flushes are serialized and terminal events await the preceding stream batch, preserving lifecycle ordering. The existing preload/IPC contract is unchanged.

The hard queue bound is 2,048 pending stream events. If reached, the incomplete batch is cleared and the store republishes authoritative app state and the current selected transcript for each subscribed view/window; it does not retain or republish selected transcripts for every affected session. This recovery path is not expected in normal operation and prevents unbounded memory.
